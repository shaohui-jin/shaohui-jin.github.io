# 项目架构设计

## 一、项目定位

`shaohui-jin.github.io` 是一个**单 Vite 应用**，把「个人博客 + 组件库文档 + 工具函数文档 + 工作流设计器」聚合在同一个站点里，构建产物直接部署到 GitHub Pages。

站点内部按领域拆成若干模块，每个模块通过 `BaseRouteRegistrar` 向路由中心注册自己的页面，壳应用（`App.vue`）只负责聚合与渲染，不重复定义业务路由。

当前仓库**不再是 monorepo**：没有 `packages/`、`examples/`、`pnpm-workspace.yaml` 与 Turborepo，源码全部在 `src/` 下，由根目录一份 `package.json` 管理。

## 四、路由与页面聚合

### 4.1 机制

- `app/core/route` 提供 `RouteRegistry` 与 `BaseRouteRegistrar`。
- 各模块（`HomeRouteRegistrar`、`CompDocRegistrar`、`ToolDocRegistrar`、`CoreDocRegistrar`、`RuleRouteRegistrar`、`BlogRouteRegistrar`）继承基类，在 `register()` 中登记顶层 Tab、分组与路由。
- [moduleRegistrars.ts](file:///d:/_myproject/shaohui-jin.github.io/src/route/moduleRegistrars.ts) 聚合全部注册器。
- [runtimeRoutes.ts](file:///d:/_myproject/shaohui-jin.github.io/src/route/runtimeRoutes.ts) 在模块加载时生成快照（顶层 Tab、分组、路由、默认路由），`App.vue` 直接消费。
- [url.ts](file:///d:/_myproject/shaohui-jin.github.io/src/route/url.ts) 负责 `/模块/路由` 与内部状态的双向换算，配合 `history.pushState` 支持深链接与前进后退。

### 4.2 强约束

- 接入壳应用的模块必须继承 `BaseRouteRegistrar`，否则 `RouteRegistry.applyRegistrar` 会跳过并告警。
- `component` 模式必须提供 `loader`；`markdown` 模式必须提供 `markdownSource` 或 `markdownLoader`，否则注册阶段抛错。
- 同一 tab 下路由 key 重复会直接抛错；缺少 tab 元数据时按 `tabKey` 生成兜底 tab 并打印告警。

## 五、内容与 Markdown 渲染

### 5.1 博客

- 内容源：`src/content/posts/<groupKey>/*.md`，文件名全局唯一，目录只表示分组。
- 元数据（标题、日期、分类、摘要、分组）由 [blog-meta.ts](file:///d:/_myproject/shaohui-jin.github.io/build/blog-meta.ts) 在构建期扫描生成，通过虚拟模块 `virtual:blog-meta` 提供给 [content/index.ts](file:///d:/_myproject/shaohui-jin.github.io/src/content/index.ts)。
- 正文使用 `import.meta.glob("./posts/**/*.md", { query: "?raw", import: "default" })` **按需加载**，不再随首包内联。
- 分组定义 `blogGroups` 是唯一来源：`BlogGroupKey` 由它推导，构建时遇到未登记的分组目录会报错。

### 5.2 组件 / 工具文档

`src/works/comp/doc/compDocs.ts`、`src/works/tools/toolDocs.ts` 仍使用 `?raw` + `eager: true` 读取，量与博客相比很小，暂未改造。

### 5.3 渲染链路

- [MarkdownRoutePage.vue](file:///d:/_myproject/shaohui-jin.github.io/src/doc-render/MarkdownRoutePage.vue) 接收 `sourceLoader`，异步取正文并渲染。
- [MarkdownRenderer.vue](file:///d:/_myproject/shaohui-jin.github.io/src/doc-render/MarkdownRenderer.vue) 把正文转成 `v-html` + 占位符，再对每个占位用 `render(vnode, el)` 挂载组件，并复用壳应用的 `appContext`（不再逐块 `createApp` + `app.use(ElementPlus)`）。
- demo 预览走 `@vue/repl` 的 iframe 隔离，并由 IntersectionObserver 懒挂载。
- Mermaid 通过 `mermaidRuntime.ts` 动态导入，不进入首包。

## 六、配置注入系统

### 6.1 链路

```text
createCompLib(userConfig?, persist?)
    ↓
resolveConfig(defaults + userConfig + localStorage)
    ↓
install(app)
  ├── app.provide(LIB_CONFIG_KEY, resolved)          → useLibConfig() 读取
  ├── app.provide(LIB_PLUGIN_KEY, { config, saveConfig }) → useLibPlugin() 读写
  └── applyCssVars(resolved)                          → 注入 --comp-* 与 --el-*
    ↓
saveConfig(newConfig) → 更新内存 + 刷新 CSS 变量 + 写 localStorage
```

### 6.2 配置优先级（从低到高）

1. `configDefaults.ts` 代码默认值
2. `createCompLib(userConfig)` 初始化传入
3. `localStorage` 持久化的值
4. `ConfigProvider` 组件级覆盖
5. 组件 `props.theme` 局部覆盖

### 6.3 对外接口

| 接口                  | 说明                                                   |
| --------------------- | ------------------------------------------------------ |
| `LibThemeConfig`      | 全局主题（品牌色、文字色、背景色、边框色、字体、圆角） |
| `LibConfig`           | 消费者传入（所有字段可选）                             |
| `PersistOptions`      | 持久化选项（enabled + key）                            |
| `LIB_CONFIG_KEY`      | 只读配置的 `InjectionKey`                              |
| `LIB_PLUGIN_KEY`      | 配置句柄（`config` + `saveConfig`）的 `InjectionKey`   |
| `useLibConfig()`      | 读取当前生效配置（含上层覆盖）                         |
| `useLibPlugin()`      | 读取句柄，调用 `saveConfig` 写回并持久化               |
| `themePresets`        | 四套预设（default / light / purple / dark）            |
| `radiusTiers(radius)` | 由中圆角推导小/中/大三档圆角                           |

### 6.4 CSS 变量命名

- 全局前缀：`--comp-*`（如 `--comp-color-primary`、`--comp-bg-page`）
- 表格局部：`--crud-bt-*`（如 `--crud-bt-row-height`）
- Element Plus 同步：`--el-color-primary`、`--el-bg-color` 等（随 `saveConfig` 刷新）

## 七、BaseTable 五模式

BaseTable 通过 `mode` prop 切换五种渲染策略：

```text
BaseTable.vue（外壳）
  ├── BaseTableElement.vue      → el-table 封装（功能最全）
  ├── BaseTableVirtual.vue      → el-table-v2 虚拟滚动
  ├── BaseTableCanvas.vue       → Canvas 2D 视口重绘
  ├── BaseTableCanvasTile.vue   → Canvas 整表预渲染 + 裁切
  └── BaseTableSkiaWasm.vue     → CanvasKit GPU 加速渲染
```

| 模式          | 适用场景               | 特点                                 |
| ------------- | ---------------------- | ------------------------------------ |
| `element`     | 常规数据量（<1000 行） | 能力最全，支持所有 Element Plus 特性 |
| `virtual`     | 万级行数据             | DOM 仍可控，虚拟滚动                 |
| `canvas`      | 超大数据、结构简单     | 单 Canvas，视口内重绘                |
| `canvas-tile` | 超大数据               | 整表预渲染，滚动裁切视口             |
| `skia-wasm`   | GPU 加速需求           | CanvasKit 渲染，按需加载 wasm        |

设计要点：

1. **统一接口**：外壳接收统一的 `columns` / `tableData` / `rowKey`，内部按 mode 分发。
2. **统一主题**：DOM 模式通过 `tableSurfaceCssVars()` 生成 CSS 变量，Canvas 模式通过 `getTableSurface()` 取 JS 常量，颜色均从 `LibThemeConfig` 派生。
3. **渐进增强**：element 模式能力最全，canvas 系模式逐步补齐 checkbox、tooltip、滚动条等交互。
4. **可选资源**：`canvaskit-wasm` 只在 skia-wasm 模式下动态导入，wasm 与中文字体由构建插件复制到 `dist/assets`。

## 十、三端适配

| 端     | 断点           | 变量             |
| ------ | -------------- | ---------------- |
| PC 端  | > 1024px       | 默认布局         |
| 平板端 | 768px ~ 1024px | `$doc-bp-tablet` |
| 手机端 | < 768px        | `$doc-bp-mobile` |

- 交互元素点击区域不小于 32×32px。
- 布局在窄屏下不溢出。
- Canvas 模式支持触摸滚动（惯性 + 方向判断）。
- 抽屉组件移动端全屏适配，并锁定滚动穿透。
- 演示站导航：平板/移动端使用底部 Tab 栏替代侧边栏，释放内容区宽度。

## 十一、组件设计模式

1. **类型先行**：类型声明统一放在 `src/works/comp/type/`，组件目录内不保留 `types.ts`。
2. **配置驱动**：BaseSearch / BaseTable 通过 JSON 配置数组描述字段/列。
3. **CRUD 联动**：BaseCrud 组合 BaseSearch + BaseTable + BaseColumnSetting + BaseSearchDrawer。
4. **列设置入口**：editColumn 列固定最右，不参与列设置面板排序。
5. **组合式函数**：复杂逻辑抽取为 `use*` hooks（如 `useCanvasScrollbar`）。
6. **插件式安装**：`createCompLib()` 工厂模式，`saveConfig()` 更新内存 + CSS 变量 + localStorage。
7. **分层导出**：配置与路由从 `@/app/core` 导出，组件从 `@/works/comp` 导出，工具函数从 `@/utils` 导出。
8. **配置派生**：业务细节颜色从统一主题自动派生，减少消费者配置负担。
9. **组件复用**：相同功能提取为通用组件（如 CodeBlock、WidgetTabs），文档站通过薄包装层复用。
10. **CSS 变量主题化**：基础组件通过 CSS 变量暴露样式控制，消费方可自定义。
11. **组件三分目录**：`basic/`（简易 UI / 图片 / 文档辅助）、`crud/`（搜索表格联动）、`interaction/`（高交互 UI）；新增组件前须确认分类，详见 `doc/组件规则流程图.md`。
