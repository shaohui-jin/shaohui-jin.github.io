## 四、P0 架构级改动

### P0-1 内容元数据与正文分离，正文改为按需加载

**问题证据**

- `src/content/posts/**/*.md` 合计约 846 KB；`eager: true` 会全部内联进入口 chunk。
- 启动时对全部文章执行 `parseFrontmatter`；[homeData.ts](file:///d:/_myproject/shaohui-jin.github.io/src/pages/home/homeData.ts#L244-L257) 还会为每篇生成摘要（全量正文扫描）。
- 组件文档、工具文档同样全量内联。

**方案：新增构建期元数据虚拟模块，正文走懒加载**

1. 新建 `build/content-meta.ts`：
   - 导出 `contentMetaPlugin(): Plugin`，`resolveId/load` 提供 `virtual:content-meta`（内部 id 以 `\0` 开头）。
   - 用 `node:fs` 递归扫描三个目录：`src/content/posts`、`src/works/comp/doc/docs`、`src/works/tools/docs`。
   - 直接复用 [parseFrontmatter.ts](file:///d:/_myproject/shaohui-jin.github.io/src/doc-render/parseFrontmatter.ts) 解析 frontmatter（Vite 打包配置时会转译 TS 依赖）。
   - 生成并导出 `blogMeta` / `compMeta` / `toolMeta`，字段：`file`（相对路径，如 `vue/vue-lifecycle.md`）、`key`、`label`、`groupKey`、`order`、`date`、`category`、`headerDepth`、`excerpt`（仅博客）。
   - 在 `configureServer` 中监听三个目录的 `.md` 变化，`server.moduleGraph.invalidateModule` 使虚拟模块热更新。
2. 新建 `src/content/excerpt.ts`：把 [homeData.ts](file:///d:/_myproject/shaohui-jin.github.io/src/pages/home/homeData.ts#L191-L234) 的 `toExcerpt` 迁移为 `buildExcerpt(source, limit)`，构建插件与首页共用，避免两份逻辑。
3. 改造三个内容索引：
   - `src/content/index.ts`：删除 `eager: true` 与 `source` 字段，改为
     `const sources = import.meta.glob("./posts/**/*.md", { query: "?raw", import: "default" })`，
     并导出 `loadBlogSource(file: string): Promise<string>`（按 `./posts/${file}` 取 loader）。
   - `compDocs.ts`、`toolDocs.ts` 同样：元数据来自 `virtual:content-meta`，正文由 `loadCompSource/loadToolSource` 懒加载。
4. 路由层支持懒加载正文：
   - [types.ts](file:///d:/_myproject/shaohui-jin.github.io/src/app/core/route/types.ts)：`RouteRecord` 增加 `markdownLoader?: () => Promise<string>`。
   - [RouteRegistry.ts](file:///d:/_myproject/shaohui-jin.github.io/src/app/core/route/RouteRegistry.ts#L45-L54)：markdown 模式校验改为 `!markdownSource && !markdownLoader` 才报错。
   - [runtimeRoutes.ts](file:///d:/_myproject/shaohui-jin.github.io/src/route/runtimeRoutes.ts#L42-L57)：markdown 路由传 `sourceLoader: route.markdownLoader`，不再传 `source`。
   - [MarkdownRoutePage.vue](file:///d:/_myproject/shaohui-jin.github.io/src/doc-render/MarkdownRoutePage.vue)：接收 `sourceLoader`，用 `watchEffect` 加载并维护 `loading` 状态；用取消标记避免快速切页时旧请求覆盖新内容。
5. 更新注册器：
   - [BlogRouteRegistrar.ts](file:///d:/_myproject/shaohui-jin.github.io/src/pages/blog/BlogRouteRegistrar.ts)、[CompDocRegistrar.ts](file:///d:/_myproject/shaohui-jin.github.io/src/works/comp/doc/CompDocRegistrar.ts)、[ToolDocRegistrar.ts](file:///d:/_myproject/shaohui-jin.github.io/src/works/tools/ToolDocRegistrar.ts) 改为传 `markdownLoader`。
6. 类型声明：在 [env.d.ts](file:///d:/_myproject/shaohui-jin.github.io/src/env.d.ts) 增加 `declare module "virtual:content-meta"`，字段与插件输出一致。
7. `homeData.ts` 改为从 `virtual:content-meta` 读取元数据与 `excerpt`，删除本地 `toExcerpt` 与对正文的依赖。

**验收标准**：`pnpm build` 后入口 chunk 体积较改造前下降约 800 KB；首页文章卡标题/摘要/日期不变；任一文章深链接可直接打开。

### P0-2 Markdown 渲染器改为单应用、`render()` 挂载

**问题证据**

[MarkdownRenderer.vue](file:///d:/_myproject/shaohui-jin.github.io/src/doc-render/MarkdownRenderer.vue#L48-L129) 对每个代码块、API 表、预览块、提示块调用 `createApp(...)`；其中第 86、104、121 行还各自 `app.use(ElementPlus, { locale })`。组件文档里大量代码块意味着成规模的应用实例与插件重复安装。

需要区分：demo 走 `@vue/repl` 的 iframe 隔离，且由 IntersectionObserver 懒挂载，这是合理的刻意设计，本次不改 iframe 方案；要改的只是外层挂载方式与 ElementPlus 重复安装。

**方案**

1. 引入 `getCurrentInstance` 与 `render`（来自 `vue`）：
   - 新增 `mountVNode(Comp, props, el)`：`const vnode = createVNode(Comp, props); vnode.appContext = instance.appContext; render(vnode, el)`。
   - 所有 `createApp(...).mount(el)` 改为 `mountVNode(...)`；记录 `{ el }`，卸载时 `render(null, el)`。
   - 删除每个块上的 `app.use(ElementPlus, ...)`：`appContext` 携带了全局组件注册与 `globalProperties`，`el-*` 与 `$compLibConfig` 仍可解析。

- demo 仍按原逻辑创建 iframe 外壳组件，只是改用 `render()` 挂载，不改变隔离与懒加载行为。

2. `mountedApps: App[]` 改为 `mountedTargets: HTMLElement[]`；`unmountDemos` 改为遍历 `render(null, el)` 后清空。
3. `mountCallouts` 的 `while (pending)` 改为「初始查询一次 + 处理过程中把新产生的 `[data-callout-index]` 入队」的单向队列，避免每轮全量 `querySelectorAll`。
4. 其余懒挂载（IntersectionObserver）逻辑保持不变。

**验收标准**：CRUD 文档页与含 20+ demo 的博客页正常渲染；`el-*` 组件在 `CodeBlock`/`ApiTable` 内仍能解析；切页后 `render(null, el)` 清空挂载点，无重复挂载或内容叠加。

### P0-3 消除 workflow 类型检查缺口

**问题证据**

- 主 tsconfig 排除 `src/works/workflow/**`，并通过 `paths` 把 `@/works/workflow` 指向 shim。
- [shims/workflow.ts](file:///d:/_myproject/shaohui-jin.github.io/src/shims/workflow.ts) 的 `RuleRouteRegistrar` 与真实 [RuleRouteRegistrar.ts](file:///d:/_myproject/shaohui-jin.github.io/src/works/workflow/route/RuleRouteRegistrar.ts) 元数据不同（真实版有分组「画布」、tag「流程」，shim 没有）。类型检查通过不代表运行时注册正确。
- [tsconfig.workflow.json](file:///d:/_myproject/shaohui-jin.github.io/tsconfig.workflow.json) 关闭了 `strict`、`noImplicitAny`、`strictNullChecks`。

**方案（分两步，最终收敛为单配置）**

1. 收紧 workflow 配置：把 `tsconfig.workflow.json` 的 `strict/noImplicitAny/strictNullChecks` 改为继承基础严格配置，仅保留必要的 `verbatimModuleSyntax: false`；运行 `pnpm typecheck` 修复 workflow 内报错（类型补全、隐式 any 标注；外部库边界（X6、monaco）允许局部断言，不整文件 `any`）。
2. 合并类型检查：
   - `tsconfig.json` 删除 `exclude` 里的 `src/works/workflow/**`，删除 `paths` 中 `@/works/workflow` 别名。
   - 删除 `src/shims/workflow.ts`、`tsconfig.workflow.json`。
   - `package.json` 的 `typecheck` 改为单条 `vue-tsc --noEmit -p tsconfig.json`。
   - 若主配置的 `verbatimModuleSyntax` 与 workflow 旧写法冲突，则在 `tsconfig.json` 中统一设为 `false`（不改动业务代码语义）。

**验收标准**：`pnpm typecheck` 通过且输出中不再出现 shim；把真实 registrar 的 label 改错时类型检查/启动能暴露问题（本项以代码走查确认）。
